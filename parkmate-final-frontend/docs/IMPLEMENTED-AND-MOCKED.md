## Not implemented / not represented as available

No payment processing, geocoding, turn-by-turn/live maps, real distance computation for free-text locations, traffic data, email provider, user-to-user messaging, admin review queue, or provider permission endpoint. The same-day uniqueness check is a browser preflight, not a server constraint; simultaneous requests from another client require a backend uniqueness rule to guarantee safety. There are no listing-specific photos; all current hero/detail visuals are illustrative. No existing backend file is copied into or changed by this project. The demo's local persistence is a front-end prototype, not a database or durable reservation system.


## Sign-in gate and color modes

Only `/auth/sign-in` and `/auth/sign-up` are publicly rendered routes. `App` waits for live-session recovery, redirects every other unauthenticated page path to sign-in with a safe same-site return path, and resumes that page only after a demo or Supabase user is present. A live signup that needs email confirmation does not unlock the app. This is client-side route protection; the static bundle remains public and real data authorization must continue to be enforced by the existing backend/API.

The auth form presents dedicated Consumer and Provider buttons before the credentials; signed-in users can switch views in the header or the mobile menu. The switch is a front-end workspace preference, not an authorization grant. `ThemeProvider` persists Light or Dark preference locally and updates the favicon/theme-color metadata. Light mode preserves the prior evergreen/ivory/sage UI; Dark mode follows the supplied near-black/charcoal and magenta-pink reference. The UI wordmark uses the exact case `ParkMate`, with a theme-colored in-app symbol and favicon.
